## 1. 唯一问题与白话收入机制

在买价买入、卖价卖出，实际成交价差可能产生收入；手续费、库存价格变化、退出及重新排队成本会吃掉收入。过滤只可能改变接到哪些成交：少接坏成交也可能少接好成交、撤单太晚仍成交，或重挂后排不上。

唯一问题：相同基础报价、初始资产和风险规则下，F按过去成交流暂停一侧，相比H按原固定时间哈希暂停一侧，在有限、事前冻结的队列/延迟模型中是否提高全账净结果，且F自身净额为正？只比较F/H两臂，不加无过滤臂。0.1413bp条件标签差不是单笔收入、账户收益或可直接减费的毛利。

## 3. 完全共同的基础政策与提示预算

固定Bitstamp BTCUSD现货、2026-05-01及06-01，两日分别5000USD现金、BTC0起步，不滚动挑日，无杠杆/借币/裸卖。第一条已收到且有效完整BBO给p0，固定q=50USD/p0；数量、价格为模型单位，不声称历史最小量/步长合法。真实交易合法性另核，不因未知拦住模型定义；未来实现须事前固定精确十进制运算/保守取整而不调收益。

共同整秒决策网格为UTC00:00:05至23:59:54。每侧最多一张post-only限价单，买价/卖价均取决策前严格已收到的有效best bid/ask。报价量q；现金含买入maker费全额预留，卖单预留已拥有可用BTC；现金不得负，库存及未完买单总量不得超过50q。库存不足不能卖，资金不足不能买；不因某臂少成交而事后补库存。F/H同公式，不同成交引起的后续库存/可报价分歧保留，正是政策后果。

两臂只在**共同合格且非零z**网格各暂停一侧：F沿既有笔数z符号（过去1秒已收到主动买减主动卖/总笔数，非uniqueID/量）；z>0暂停卖侧，z<0暂停买侧。H沿既有SHA256 `XTX-adverse-proxy-v1|YYYY-MM-DDTHH:MM:SSZ`：首字节<128暂停买，否则暂停卖。沿原capture/source guard、输入缺口及精度裁定，不利用未来被动side标签作输入。z=0/无评分两臂不额外信号暂停。共同安全未知（明确断连、BBO陈旧>1秒/同戳冲突、输入时序不可判）则两臂暂停新单、发全撤；未知区段不能删除已存订单/成交/库存，经济结果不可封闭时按§7不可判定。

“各暂停一侧”匹配事前提示预算，**不匹配事后成交数、成交量、资金使用或仓位**；没有库存的一侧被提示，也不改成暂停另一侧来凑实际活动。

## 4. 最少两个有限执行情景，先冻结后结果

主情景M：从collector已知决策时刻到模型订单接受/撤单生效均固定100ms；压力情景S：均500ms。两者完全在supplier collector capture clock下排程，是模型接受/撤单时刻，**不是实测到所/撤单生效**，不能解释为真实500ms预测期剩余可用时间。只使用这两个，不扫延迟找盈利。所有政策共用同一外生历史、时钟和情景，不随机挑有利延迟；假设小单无市场冲击、无对手反应、无隐藏/优先订单，仅为条件模型。

1. **决策、提交、接受。** 只看决策截止前信息，先发撤单/新单意图，延迟后接受；同侧已有待接受/活跃/待撤单则不再挂。接受时引擎可用当时已到达的历史事件检查被动性，策略本身不得提前看这些未来信息。若买价>=当时ask或卖价<=bid则post-only拒绝，不转taker。无有效报价则该次接受未知，不能假定成功或无成本消失。
2. **模型排队。** 接受时以严格早于接受时刻、年龄≤1秒的最新有效snapshot25，取本单同价同侧可见总量为队前量a；该价不在25档或时钟冲突则未知，不设a=0。若明确在可见范围内而无该价，a=0仅是模型假设。该聚合量并不代表真实队位，快照采样中间路径也未识别。
3. **消耗和部分成交。** 只让模型接受后、模型取消生效前、同价且主动方向相容的已收到raw打印成交数量消耗a：type0主动买消耗卖单，type1主动卖消耗买单。数量只取已存raw的amount_str/amount，用Decimal、单位BTC；重复tradeID不重复消耗。先耗a，剩余才分配给自身未成交量r，最多r；保留部分成交。还须通过下一条源钟迟到guard；collector收到较晚不自动表示撮合较晚。打印穿价、BBO碰价不自动fill，盘口撤减不给队前进收益；不从以后真实orderID倒推自己的报价/成交。相同打印量在F/H各自平行世界独立用同一映射，不把别人的实际成交复制为我们的事实。
4. **撤单、寿命、再挂。** 单从接受起1秒期满发撤单；信号暂停或共同安全暂停也可提前发撤单。生效前继续承受模型成交，撤单在途不释放资金/库存或重挂；生效后释放余量。改价必须撤后再挂，重新以当时快照设a，绝不继承旧优先级；下一整秒才可发新单。成交全部完成后也等下一网格。1秒是报价寿命/更新周期，**不是每笔库存强制平仓**。
5. **同戳与缺口。** 七位collector钟用整数100ns ticks，原生source与CSV保留既有µs量化界。跨类型同capture不借行号猜真实先后：模型固定先处理已有订单的打印成交、后处理接受/取消；模型接受单不能吃同capture打印，撤单则未赶上该capture打印。必须明示这只是一个固定竞态约定。若量化区间跨关键接受/取消边界或断连导致存续/成交不可判，则涉及路径标UNKNOWN，不能静默跳过/删分母。相同capture同价同方向打印先合量处理，非事后按orderID挑分配；重复tradeID按原身份QC拒绝。

6. **源钟迟到guard及其假设。** 为不把迟到报告自动算作接受后可获成交，模型额外明确假设source UTC与collector UTC共轴且跨钟误差不超过1ms；这是未实测的模型假设，不是供应商已认证精度。native source微秒量化区间再向两边扩1ms，与模型接受/取消时刻区间比较：确定在接受前的撮合报告不耗队列；只有source整个区间严格晚于接受且严格早于取消、capture也在模型活跃区间内才可消耗。跨任何边界的源区间为UNKNOWN，不靠行号或后来orderID消歧；成交源戳还须严格超过接受前已知全部trade源戳最大值。接受时锚定的snapshot源时刻也须在此假设下确定早于接受，无法判则UNKNOWN。实际跨钟误差仍未知，故模型成交不认证真实个人成交；两个有限情景均共用这一假设，不新增误差网格。

交易源钟guard用于避免明显迟到/时间矛盾；不得把collector延迟情景冒充交易所撮合时钟真值。接受前快照和成交打印只定义模型，可能低估或高估真实获单，两个情景都不被称为实际保守界。若无法判别关键事件，保留路径UNKNOWN而非假定订单“刚好赶上”。

## 6. 完整现金库存账及同风险比较

买成交：现金减p×量及maker费，BTC增量；卖成交：BTC减量，现金增p×量减maker费。**主/压力均固定每次maker成交0.30%，仅taker成交0.40%**，以USD扣费的模型假设。两次maker完成买卖应各计一次maker费；不是每个报告固定70bp，终端taker才另扣taker费。公开参考费用不是两历史日或个人账户实费；不确认个人权益也能做这个明确假设的模型研究，不能认证个人净利。零费/返佣不加第三情景。

UTC23:59:55共同停止新挂、全撤；最迟生效后固定23:59:56起统一终端清算。卖清已持BTC，使用严格已知且年龄≤1秒的bid侧25档逐档扣量，价格再不利1bp，并扣0.40%taker费；无空仓回补。深度不足、终端同戳/缺口、取消状态不明则UNKNOWN，禁止mid/日内最优价结算或只清好退出的日。日终规则固定，非1秒标签强平。

两组分别保留全部候选网格、拒单、未成交、取消前fill、部分fill、重排队、错失好单、避免坏单、现金预留、库存和末端余额。完整机会成本通过F/H总净终值差体现，不将“漏掉好单”再重复扣一次；机会归因不能替代总账。每一腿实际模型成交价格已含价差，不再重复扣价差。

主量为两日等权美元净额差ΔΠ=Π_F−Π_H，同时列两臂各日绝对Π。固定5000现金同起点，不按成交数/成交名义配平或以D换算。每秒并在成交后记录共同可执行清算口径的最大库存名义、库存时间暴露、最大净值回撤、最长持仓；估值须计统一深度/滑点/退出费，无法估值则UNKNOWN。F/H都守同预算，但风险仍可能不相等。已知模型费用计全；运营、数据、资金机会成本和适用税费未认证，不记“真实0”。本有限模型将这些另列为未计外生成本，给模型净额可承受成本余额的解释而不声称完整个人利润；不另假造资金收益率或扣重复退出费。
