## 1. 暂停影响订单资格与再排队，不能直接把标签差变成收入

**代码事实。** inputs.py109–116：整秒t仅用capture在[t−1s,t)的已收到trade笔数判断主动买卖多数，边界不确定共同safety。core.py219–224：非零正号F暂停sell，负号暂停buy；H同网格用固定SHA首字节暂停一侧，零/无评分均不作额外信号暂停。run.py143–146让两臂共享sign/safety；共同提示预算不等于相同实际挂单/成交或库存。

core.py99–114：已有同侧单，暂停则请求撤单；不暂停但当前best变化也请求撤单。已有pending/active/cancel-in-flight均挡住同侧新单（88–94）；当前决策发撤后不会同格替换，等生效后的下一整秒。接受时重新按快照设ahead，同价可见量全在前、改善价ahead0（125–143）；不继承旧优先级。E只同价，X另含严格穿价压力、忽略旧ahead并按自身限价成交（20–23、167–194）。这些是固定条件模型，不是已证真实队位。

**已有标量。** 16path每条32445决策；accepted约2万至3万，fill记录远少（包含部分与终端，不是完整往返数）。费用桥May F四路径G=N+C均正、净额负；June F四路径G仍负。因而“只是手续费”不适用于所有路径，“只是没信息”也与同窗May D=.1856358775bp、June .1639667375bp的标签证据不符。D对原实际被动ID标签分层；经济账对虚拟订单生命周期，人口、参考资格及权重不同，不能一对一匹配D与自己的成交。

**推测/UNKNOWN。** 反复撤重挂可能影响成交选择与排队，但高撤单数不能证明错误、无fill不能证明错失好单；本轮没有“不撤单会成交/赚钱”的反事实。不要把此推测选作第二候选。

## 2. TTL与取消在途是报价时钟，不是库存退出时钟

**代码事实。** 接受时设expiry=accepted+1秒（core141–142）；到期仅调用cancel(reason=TTL1s)，真正取消再等固定100/500ms（95–98、122–124），提前pause/reprice也会撤。第一次撤单请求后不重新延长cancel_at；在途不释放预留，部分fill继续保留剩余单（56–65、159–165）。run136–145固定同capture先print、再任务、再决策；print须capture晚于accepted，source名义点晚于accepted及接受前已知最大source、且不晚于cancel_at（167–178）。因此取消当刻的打印按模型可先fill，刚接受单不能吃同capture打印。source边界计数不等于实测个人延迟。

TTL没有1秒强平库存；不会因持仓超过1秒自动卖。即使每张报价短命，库存可以穿越很多张单。取消请求数不等于有效取消数：请求后单可能先填完，任务找不到原ID便不再产生cancel_effective（120–123）。具体取消在途fill、拒单与reason分组由本轮Data原账输出确定；不能仅用两个总count之差代替。

## 3. 唯一候选：固定q库存的出清可售性与终端依赖

**确定结构。** 两日各5000USD/BTC0，q按当天首个合格初始BBO的50USD/p0向下取12位，整日固定（run113–119；core11）。买入预留限价名义及.003费；卖出预留已有BTC；库存连未完买单≤50q；无借币/裸卖（core56–65、88–94）。每张新卖单永远q，可用库存<q不能提交；不足量不会自动改成较小卖单。部分买/卖会改变库存，尾量可留存。卖侧与买侧使用同一F/H暂停规则，没有按库存倾斜的报价/过滤，也无独立减仓、持仓年龄退出或止损模块（decision/submit/prints完整函数）。这符合固定研究定义，不应直接叫bug。

**终端机制。** run124–151：最后决策09:00:49，09:00:50全撤；09:00:51优先严格asof，否则至52秒首个合格参考。core199–208等取消全部闭合才逐bid25档卖完，价格不利1bp、taker.004，每档只用一次，逐腿现金/fee保留、风险原子前后观察。平时maker每次.003，不能把末端卖出所得当利润，不能把每笔成本固定70bp（core25–37、145–158）。16path均terminal_done且现金完整，仍有1153等risk_unknown_count；risk引用不足不删库存、不擦除已知现金（67–85、209–217）。

**现存证据与未知。** 保存标量中例如June X100 F/H库存积分187.7669978/65.5877071 BTC秒，终端taker名义1490.9890732/94.5390290USD；但June X500 F/H为137.9443605/134.9890559 BTC秒，终端854.9559585/987.4768344USD。方向并不统一，不能以一个最差路径解释全部。库存价损归因仍UNKNOWN，终端费用可识别不等于终端全部亏损可归因。

最长BTC>0计数只在库存从0转正时开始、完全回0才清掉（core51–55、159–160）。因此约9小时非零区间不是某笔/每枚BTC持9小时；可能由小于q尾量延续，**尚需Data既定全部16path的0/<q/≥q持续时间及终端残量/q验证**。静态可能性不能冒充实际发生。

**只读下一判据（不是新规则或运行授权）。** 先用本轮Data同一次原账归纳判断：长期非零是否主要落在<q，终端是否仍有至少q的库存、是否存在有意义≥q积累。若主要是尾量，不以最长非零时长指控大量库存滞留；若终端/积分显示有意义库存持续，才将“报价信号未定义独立库存退出”保留为下一有限问题。这能低成本区分度量误读与政策机制；不能证明换退出便盈利。任何更改q、卖剩余、偏斜或持仓时钟均改变研究政策，需未来新固定实验；本轮不提出新参数、不实施。
