## 样本及唯一目标

覆盖封存两日全部16路径/8组F/H，原四情景E/X×100/500ms、原窗口/模型规则/费用固定。比较成交、撤单、库存和终端退出，最后只选一个最值得有限继续验证的转换环节。结论要分别标事实、推测、UNKNOWN；不能看一个最差例子便归因全部亏损，也不找新窗口或挑正结果。旧同窗D正只支持条件信息，旧8格F净额均负不翻案。

## Data Owner：仅原账一次流式归纳，不重建策略

先读旧result/summary/manifest、旧独立saved-ledger-audit及必要CSV字段，身份引用固定。允许独立小标准库归纳helper仅读两份旧ledger，按全部原record事件/保存状态汇总；不能import旧引擎/analysis/reader，不能读行情、重造订单/信号/标签、计算新假想收益或改费用。

固定输出对全部路径一致：
1. 提交/接受/撤单请求/生效/拒单等counts与原summary一致；cancel_sent按原detail.reason分组、请求与实际生效分开。统计accepted但最终无maker fill/部分fill/满fill订单（有充足日志才分类，不用其推算放弃了多少好成交）。不把取消数当消除坏成交数、模型fill数当完整往返笔数。
2. 原fill按buy/sell、equal/cross/terminal计数量、名义和费用；统计取消请求后/生效前或同刻打印的已存maker fill，明确模型时序、非真实延迟。实际取消后若不取消会成交/盈利的反事实UNKNOWN，不新增markout。
3. 库存使用原保存BTC状态：数量时间积分可只对已有余额相邻时间做恒等式归纳/核原inventory_BTC_seconds，不生成新持仓或价格风险路径；max BTC、最长连续BTC>0、终端前BTC和其q倍数。可以固定分0、0<库存<q、>=q的持续时间（从各路径首记录至终端），并明确这些是非零库存区间，不是每枚BTC或每笔订单的持有时长。不要用很小尾量的长期非零区间证明巨额风险。
4. 终端exit按已存fill汇总qty/notional/fee，核taker_notional×原费率、原终端见证及归零；保存最后非终端买/卖时间。可给终端剩余至少已持有1秒的数量下界=max(0,终端前BTC−终端前最近1秒已存买入量)，是数量守恒下界不作FIFO/价格成本归因，不重造交易。若日志时序不足标UNKNOWN。
5. 用固定首事件/各路径终端作少量小见证，不按盈亏挑时间。原整体风险仍UNKNOWN，不能拿max BTC或数量时间取代原三项完整风险可比门槛。

helper只跑一次全文归纳，CPU40s/128MiB/输出4MiB，在保存账上计数/加总而非重放市场。记录脚本、输入hash、PID/工具exit/CPU/wall/RSS、gzipEOF/CRC和全行覆盖。旧manifest/hash和已验全账可复用，压缩SHA可在本次顺读一起核；不为此反复扫市场或旧大账。Source本轮1次归纳失败/帽就保留缺口停，不规则后修再择优跑；普通合成/准备不含旧收益寻优。
