# 七格手续费前仍亏：原账归因与继续/停止判断

**结论：现有证据不能判定“成交流信号完全没有信息”，也没有证明“本来有可交易利润，只被退出吃掉”。更支持一个较窄结论：信号有条件风险识别迹象，但当前实际成交集合、库存与主动退出的组合，没有形成正的手续费前现金边缘。停止继续试当前兑现版本，不再调退出周期；保留信号为研究证据，不升级为赚钱方案。**

本轮只读封存代码与原账；一次描述性账归纳覆盖两账全部1,431,823行、3,631条fill、16条路径。没有重跑策略/模型、重训、调参、新行情、新标签、改费率、重算风险或交易。下表是条件模型账，不是本人真实成交。F为成交流提示组，H为固定时间哈希暂停对照；E/X为原同价队列/穿价压力情景，100/500为原毫秒时延。八格只涉及两个历史日，并非八个独立样本。

## 1. 这次到底在做什么：并未形成稳定双边价差闭环

原代码从5000美元、零BTC起步，不能空仓卖现货；先买后才有可卖库存。每批买入满1秒触发撤两侧报价，经过原两段延迟主动卖出，并在退出期间阻止新提交（core59–62、100–124、131–196）。七个完整F路径中，六格没有任何被动卖出成交；仅June X100有7条被动卖出，主要卖出仍来自到龄主动退出。全部16条路径终端强制卖出fill为0；此次亏损不能归咎于最后一刻大额终端清仓。

这不是说代码没有卖出逻辑，而是已保存结果没有实现“买卖两边都主要被动成交、反复收价差”的经济闭环。较短库存确实降低了库存数量时间，却把大部分卖出变成主动退出；前者不能替代正收益。

**已确定。** 原现金、BTC、费用、成交分组及可用G=V+X恒等式一致，未发现能由本次账式直接确认并翻转结果的现金记账错误；不等于真实撮合得到认证。短库存方案主要是被动买入/主动卖出，买入项五格已不利、库存项七格负、退出项七格负；单怪手续费、固定1bp或终端卖出均不足。

**较有支持的解释。** 信号并非在这两个历史前缀完全丢失原条件信息，但信息强度、实际获单选择和当前卖出方式没有组合成正毛边缘；执行与库存转换确实存在负贡献，不能只用“AI/信号完全没用”概括。尚不能证明存在原本可兑现的正利润被某单一转换环节吃掉，也不能证明换一种退出就能兑现。
