# LOBFrame研究推进：标签、许可、免费数据与60秒报价成本

读取与核算日期：2026-10-21。原目标仍是寻找个人能复制的净赚钱环节；没有证明预测优势、净盈利或资金容量。本报告收敛在盘口预测，不转向年度配置或清算服务。

## 当前判断

免费历史盘口数据这一前提已经取得实物证据；LOBFrame标签有必须处理的时序/分支问题；代码不能直接当作可商业使用的现成实现。新增的固定报价算术表明，短周期主动吃单对成本极其敏感。

建议保留盘口研究材料，暂缓启动60秒主动吃单模型实验。下一道门是明确实际可用的费用与数据时效是否允许留下足够空间，再讨论模型能否事前识别。当前不能说已复制XTX，不能从单日统计否定全部盘口预测。

## 1. 已核清的三个前提

### 标签与时间

代码固定在 commit c47549dc967a884354152bf2484331e11be03023（2024-05-31）。raw标签是未来第h个处理后观测与当前中间价之差，不是收益百分比，h=10/50/100也不是10/50/100秒。中间价是最优买价、最优卖价的平均。

数据集输入切片为[s,s+W)，标签取s+W这一行；例如W=100、h=10，输入0—99，目标为m110−m100，存在一行间隔，不能据此直接宣称未来信息泄漏。smooth分支中，抽样选用的标签组与最终返回的raw标签组不一致；平滑构造也不应照注释理解为未来均价。这些结论来自静态源码，不是运行认证。

来源：[标签生成](https://github.com/FinancialComputingUCL/LOBFrame/blob/c47549dc967a884354152bf2484331e11be03023/data_processing/data_process.py#L403-L415)、[样本切片及标签返回](https://github.com/FinancialComputingUCL/LOBFrame/blob/c47549dc967a884354152bf2484331e11be03023/loaders/custom_dataset.py#L260-L316)。

## 2. 本次新增的报价算术

只问：在固定历史时点引用买入ask，约60秒后引用卖出bid，报价之差能否覆盖既定费用？没有模型、预测、策略信号、仓位、资金曲线或假想美元利润。

- 数据：上述同一已封存文件，不补日期、不换样本。
- 固定网格：UTC 00:05起，每120秒一个时点，共715个。
- 两组引用时刻：入/出目标均分别增加1秒或5秒。它们是时间假设，不是实测本机延迟。实际引用目标之后首条合并记录；相同采集时间戳保留最后状态。
- 每条腿等待超过1秒、与上一合并记录间隔超过2秒等不符合条件，排除整个共同槽；不向后找更有利报价。
- 每边额外不利滑点1bp；手续费每边0/5/10/25/50bp。1bp=0.01%。这些是情景假设，不是用户真实费率。
- 报价空间公式：`10000 × [bid_out × (1−slip) × (1−fee) / (ask_in × (1+slip) × (1+fee)) − 1]`。正值仅表示该组报价在这些假设下留有空间，不是已实现收益。
- 两延迟共用709个有效槽；6槽排除，仍为UNKNOWN。四个UTC六小时块分别175/179/179/176槽。观察覆盖门槛满足，不代表统计盈利门槛通过。

| 每边手续费 | 1秒假设下正空间槽/709 | 5秒假设下正空间槽/709 |
|---|---:|---:|
| 0 | 195 | 197 |
| 0.05%（5bp） | 12 | 12 |
| 0.10%（10bp） | 0 | 2 |
| 0.25%（25bp） | 0 | 0 |
| 0.50%（50bp） | 0 | 0 |

每边5bp时，最大单槽报价空间分别约9.907bp和15.246bp；不是平均值。5秒/10bp场景的两槽仅在同一个六小时块，一槽占两槽正空间和约90.5%。不能把少量事后正窗口包装为稳定机会，也不能解释为延迟越大越好：两组的入场和出场引用时刻同时改变。

## 3. 能得出与不能得出的结论

可以得出：本日固定多头主动吃单、固定约60秒与固定网格下，成本压缩空间明显。每边25/50bp的709个共同有效槽无正空间；6个排除槽未知。每边5bp仍有12个事后正窗口，未检验任何模型能否在事前选择它们并避开亏损窗口。

不能得出：所有时点/日期/期限或空头均无机会；挂单做市也无机会；真实成交、成交量、排队、冲击、完整运营成本、税费或容量已验证。不能从报价对数推算任务数量、账户利润、胜率或复利财富路径。

第一性原理顺序：有历史可用数据 → 有事前可知的增量信息 → 在可成交时刻仍能覆盖成本 → 留出期稳定 → 资金扩大仍成立。目前只跨过历史数据入口，本次检查的是后面成本环节的一个必要条件，尚未跨过预测优势这一关。

唯一值得准备的后续验证仍是“十档盘口相对价格与价差，是否增加可兑现的短期信息”。正式前须先固定真实可用费率/延迟边界、与模型输出对应的标签和留出时期；不得把本次已看过的报价正窗口用于挑模型或阈值。当前不启动该模型验证。
