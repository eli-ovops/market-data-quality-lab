# 成交方式与个人复制边界：费用假设是否错杀了当前模型

研究日期：2026-10-21；Root整合两位原Owner的有限只读审阅及官方来源。新增付款0；无开发、安装、模型运行、行情读取、新回测、账户连接或交易。原A的STOP及封存结果保持。

## 结论先行

**本次模型失败不能归咎于25bp费用，它先在训练能力门槛失败，尚未核算收益。改成挂单也不能使这套配置自动变得合格。** 另一方面，既有主动吃单的成本结果不否定所有被动做市机会：两种业务需要分别检验，不能互换成交假设。

本轮一个具体的新发现是：已知开源框架HftBacktest的《Making Multiple Markets》教程，明确采用最高档maker返佣，并披露单位问题。它提供可复用的执行研究方法，却不能直接提供普通个人可复制的净盈利证据。该框架10月18日已进入我们的研究，本轮没有将它包装为新发现或重新启动其旧样本。

## 1. 把XTX与个人实验放回正确位置

XTX客户页披露，它提供按客户交易流定制的双边流动性，并承担一定时间的风险；eFX条款还明确报价价差、不同接单条件与执行费。这说明价格预测嵌在报价、承接与退出流程里。这里仅核其公开业务机制，不声称知道XTX利润最大的策略或各环节贡献。

来源：[客户页](https://about.xtxmarkets.com/clients/)、[eFX条款](https://www.xtxmarkets.com/assets/disclosures/global-efx-trading-practices-disclosures.pdf)，后者正文第1—4页；读取日2026-10-21，文档发布日期UNKNOWN。

用白话表达的研究链条是：

**当时可得信息 → 对未来价格/风险的判断 → 选择报价与交易条件 → 部分订单实际成交 → 管理库存与退出 → 扣全成本后的损益。**

我们现在的自建A只检验了第一部分的一个适配，尚未证明基本学习能力。个人主动买ask、卖bid的路线还要支付即时成交的价差与费用；被动挂单则把一部分成本问题变成等待、排队、未成交及成交后风险。这是机制分析，不能据此说挂单一定优于主动交易或XTX必然靠某一环节盈利。

## 3. 改挂单究竟缺什么

Bitstamp官方Maker-Or-Cancel规则可避免订单在提交时立即全部或部分吃单，不保证以后成交。现有Tardis L2快照只有聚合价量与供应商时间戳，缺自身订单的到达、排队及成交/撤单确认。触价或深度下降不能叫自己的成交。

来源：[Bitstamp官方API](https://www.bitstamp.net/api/)、[Tardis快照schema](https://docs.tardis.dev/downloadable-csv-files/data-types#book_snapshot_25)，读取日2026-10-21。完整定义及独立论文边界见[成交Owner审阅](fills/passive-fill-applicability.md)。

个人想赚到的不是“屏幕两边报价的差”，而是**真正成交的订单，在随后退出并扣成本之后留下的钱**。需要分开四件事：

1. 能否在信号失效前到达并排到成交；
2. 恰好被成交时，价格是否更容易往不利方向走，即逆向选择；
3. 只有一边成交后，库存怎样退出，是否要支付主动对冲成本；
4. 实际已成交数量对应的费率、冲击、资金占用及运营成本。

不能要求先取得完美私人账才允许任何研究。L2加逐笔成交可支持带明确假设的执行估计和敏感性分析；但估计不升级为真实成交证明，结果也不能脱离队列与时延假设外推。

## 4. 有现成轮子，但要识别教程隐藏的经济条件

[HftBacktest官方成交文档](https://hftbacktest.readthedocs.io/en/latest/order_fill.html)提供部分成交、队列和时延处理，并明确历史回放不改变市场、不包含市场冲击。缺逐订单数据时需估计队列；其保守队列模型仍是模型，不是个人订单的真实下界保证。

[当前仓库](https://github.com/nkaz001/hftbacktest)及[根LICENSE](https://github.com/nkaz001/hftbacktest/blob/master/LICENSE)可读，软件MIT许可要求保留通知；这不自动授权所有外部行情。这里没有安装、运行、审完全部源码或固定最新commit，不能当已验收的实现版本。

[Making Multiple Markets教程](https://hftbacktest.readthedocs.io/en/latest/tutorials/Making%20Multiple%20Markets.html)正文与所示配置确认：

- maker设为−0.00005，即0.005%返佣；页面称是对应项目最高档。个人能否获得UNKNOWN，不能移植为个人条件。
- 同页披露交易强度使用半tick而非tick，为保留旧结果未修改。影响量级没有独立重算，不推定全部结果虚假。
- 演示显式切换不同延迟数据，使用概率队列及无部分成交设置。带有“live_order_latency”的输入是时延样本线索，不等于教程净值是实盘账户净值。

上述页面读取日均2026-10-21，教程发布日期/当前固定构建commit UNKNOWN。本轮审的是相关文字与配置段，未读取图中精确收益或全部源码，也未取得完整成交、费用与资金原账。因此不能归因“教程利润都来自返佣”，更不能凭曲线承诺盈利或容量。

## 5. 当前明确决定

**不重启A，不直接替换maker费率，不以触价即成交的模拟恢复盈利结论。** 可以复用现成执行研究框架的思想，减少未来重复造轮子；当前还没有值得复制投入资金的完整短期预测闭环。

继续同一方向时，唯一应优先补的经济证据是：一个规则/预测固定的公开盘口案例，在可核成交模型、个人可得的费用与时延假设下，能否保留独立时期的净优势，并披露假设敏感性。无法拿到真实订单账时先降低结论等级，不把假想成交叫获利，也不把缺账当整个方向不可行。

此处只确定证据问题，不启动新模型、回放或策略支线。已停止的A保持原判；未测B、样本外、盈利和容量仍UNKNOWN。当前财富目标尚未实现，也没有可据此外推的达标收益率或期限。
